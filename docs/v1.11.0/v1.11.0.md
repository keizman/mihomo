# v1.11.0 Android 复测报告 (2026-02-25)

## 测试目标

在 Android 真机上复测 `net-sim` 功能有效性，尽量使用内网链路，避免公网波动干扰结论。

## 测试环境

- 日期: 2026-02-25
- 设备: Pixel 7 Pro (`192.168.8.100:5555`)
- App: Clash Meta `2.15.1.Meta`
- Android 配置: `net-sim.enabled: true`, `latency: 200` (通过 profile 加载)
- Windows 主机: `192.168.8.101`
- 本地服务: Python HTTP server (`/ping`, `/blob`, `/upload`)
- 数据路径:
  - 控制面: `adb forward tcp:19090 tcp:9090` 后从 Windows 调 `http://127.0.0.1:19090/net-sim`
  - 数据面: Windows `curl --proxy http://192.168.8.100:7890 ...` 经过 Android Clash

## 结论

- Android 端 `net-sim` 大部分功能已生效: 延迟、抖动、丢包、损坏、重复、突发、API 动态调参。
- 发现一个明确问题: **下载方向带宽限速未生效**，仅上行限速表现正常。

## 修复说明 (同日补充)

- 修复文件: `component/netsim/conn.go`
- 修复内容:
  - 删除 `Read()` 中“仅 `DirectionDownload` 限速”的逻辑
  - 改为在 `Write()` 按连接方向统一限速: `e.getLimiter(c.dir)`
  - 对应关系:
    - `inbound(DirectionDownload).Write` -> 下载方向限速
    - `outbound(DirectionUpload).Write` -> 上传方向限速
- 新增回归测试: `component/netsim/conn_test.go`
  - `TestDownloadBandwidthThrottleOnWrite`

## 问题定位

从实现看，`handleSocket` 对连接方向包装如下:

- `inbound = WrapConn(inbound, DirectionDownload)`
- `outbound = WrapConn(outbound, DirectionUpload)`

而 `conn.go` 中限速触发条件是:

- `Read()` 仅 `DirectionDownload` 执行下载限速
- `Write()` 仅 `DirectionUpload` 执行上传限速

该组合会导致下载流量路径未命中下载限速，上传路径可命中上传限速。表现与本次 Android 实测一致。

功能释义

latency: 200
# 单向基础延迟（ms）
# TCP：Send + Recv + Read + Write 都加，影响更重（RTT 和吞吐都明显受影响）实际测试最终延迟 = latency * 4
# UDP：Send 路径一次、Recv 路径一次（更接近每方向一次）实际测试最终延迟 = latency * 2 (如果不需要收包则不用 *2)

jitter: 50
# 单向延迟抖动（ms），在 latency 基础上做 ±jitter 随机波动

loss: 1.0
# 随机丢包率（%）

bandwidth: 10
# 对称带宽上限（Mbps），同时作用于上/下行

upload-bandwidth: 5
# 上行带宽上限（Mbps），设置后覆盖 bandwidth 的上行值

download-bandwidth: 15
# 下行带宽上限（Mbps），设置后覆盖 bandwidth 的下行值

corruption: 0.5
# 包损坏概率（%），随机篡改包内容（比特翻转）

duplication: 0.2
# 包重复概率（%），随机额外复制并发送一次

reordering: 5.0
# 包乱序概率（%）
# 当前版本该字段可配置，但实际重排发送逻辑未完全接入（可视为预留能力）

burst-loss: 2
# 突发丢包强度：最多连续丢包数
# 当 burst-loss > 0 时，普通 loss 不再按“单包随机丢弃”执行；loss 只作为“触发一次突发连丢”的概率。
# 所以 loss=5、burst-loss=2 时，可近似理解为 5% * 2 ≈ 10%（长期更精确约 9.5%）。

burst-delay: 100
# 突发额外延迟上限（ms），在正常延迟上额外加 0~burst-delay
# 有 loss 时：触发概率使用 loss
# 无 loss 时：默认按 5% 进入突发状态
# 建议搭配 latency/jitter 使用，更接近真实弱网（如地铁/电梯）

packet-size: 1500
# 包大小限制（bytes），超出会被截断（slice），不是分片发送
# 主要在 UDP 路径体现，TCP 不按该字段做分片仿真

queue-type: fifo
# 队列策略：fifo / prio / fair-queue
# 当前实际生效为 fifo；prio 和 fair-queue 仅识别配置，行为暂同 fifo
